# v0.1 release readiness

AI-SDLC `0.1.0` is the first externally consumable protocol/reference-implementation baseline. The repository may freeze and validate the baseline before publishing a GitHub Release or version tag.

## Baseline definition

The machine-readable release contract is:

```text
VERSION
release/v0.1.0.yaml
```

`release/v0.1.0.yaml` declares every normative JSON Schema, supported Workflow Profile, reference control-plane entry point, required operating/security document, CI validator, runtime support level, and any known blocker that must clear before tag publication.

`python scripts/validate_release_readiness.py` verifies the declaration against the repository and CI wiring.

## What v0.1 means

The `0.1.0` baseline includes a working control plane for:

```text
Bootstrap
→ Feature Manifest
→ Commander / Orchestrator
→ Runtime Router
→ Runtime Task / Dispatch Contract
→ Feature Event / Evidence
→ Event Inbox
→ Transition
→ Persistence Plan
→ revision-safe Git persistence
→ next Commander state
```

It includes Project Adapter and cross-repository GitHub installation contracts, ChatGPT Web/manual Task Packages, and an executable reference boundary for `gh-aw/autonomous` dispatch/result transport.

The gh-aw reference adapter has now completed one real bounded autonomous dogfood cycle using the DeepSeek profile. Runtime run `31241252417` produced PR #110 and durable runtime evidence; review, code gate, verification and verification gate were then persisted through Feature Events to revision 7 / workflow `DONE`. Agent Orchestrator remains routing-only.

## Compatibility

The baseline uses the policy in `docs/protocol-versioning.md`.

Important pre-release compatibility decisions preserved in v0.1 include:

- legacy Feature Manifests without `revision` are interpreted as revision 0;
- low-level Feature Events may omit `id`/`expected_revision` for earlier 0.1 compatibility;
- repository Event Inbox persistence is intentionally stricter and requires explicit identity/revision preconditions;
- Project Adapter is optional; projects without it retain the reference Commander's prior default behavior.

No migration from an earlier public AI-SDLC release is required because `0.1.0` is the first externalized baseline.

## Release gates

A GitHub Release/tag must not be published until:

1. full repository CI is green on `main`;
2. `validate_release_readiness.py` passes;
3. no release-blocking Security Review finding is open;
4. every blocker declared in `release/v0.1.0.yaml` is cleared;
5. the StarringV6Test second-repository installation dogfood passes using an immutable AI-SDLC SHA;
6. the gh-aw autonomous runtime dogfood executes one real bounded work unit and returns durable PR/evidence state;
7. `CHANGELOG.md` accurately describes known limitations.

The two previously declared blockers are now cleared:

- Issue #6: DeepSeek autonomous gh-aw dogfood passed with runtime run `31241252417`, PR #110, validation run `31241812708`, and Feature `F-GHAW-DEEPSEEK-0001` reaching revision 7 / workflow `DONE`.

`known_release_blockers` is therefore empty. The repository remains `release-candidate` until the cleanup PR is merged and full `main` CI is green on the resulting release candidate commit.

## Production pin policy

A human-facing release tag may identify the release, but target-repository workflows should pin the reviewed full commit SHA. Caller templates intentionally use `REPLACE_WITH_AI_SDLC_FULL_SHA` until installation substitutes that SHA.

## Legacy dogfood Issue cleanup

The first dogfood cycle intentionally over-modeled Requirements/Design/Plan/Gate/Artifact evidence as separate GitHub Issues. That experiment showed unacceptable bookkeeping overhead.

The accepted model is now:

```text
Feature Issue
  + Feature Manifest
  + repository Artifacts/Evidence
  + true executable Work Unit Issues when needed
```

Obsolete bookkeeping-only Issues may remain closed; repository artifacts and Git history retain their audit trail. Feature-specific one-shot/recovery workflows should be removed after their evidence has been durably captured so the release surface contains only reusable runtime/control-plane tooling.
